# ADR 0002 — MCP server, editing in the interface and generated tracker

**English** · [Français](0002-mcp-and-tracker.fr.md)

Date: 02/11/2026 · Status: accepted

> The tool, field and command names quoted are those of the time, in French; the code and the API have since moved to English (for example `ajouter_evenement` → `add_event`, `noter_lot` → `score_batch`, `grille` → `rubric`).

## Context

Sprint 2: connect vigie-emploi to an AI without going through the CLI, edit scores and applications from the dashboard, and make the database the source of the application tracker (`_SUIVI.md`), kept by hand until now. Also fix two flaws of the sprint 1 import (grouped rows of the register, tracker / register duplicates).

## Decisions

1. **Official MCP server, stdio transport** (`@modelcontextprotocol/sdk` 1.32, `McpServer.registerTool`, Zod 4 schemas). Command `vigie-emploi mcp`, loaded on demand (the SDK is not imported by the other commands). Twelve tools with names and descriptions in French: that is what the AI reads. No HTTP transport: local use, one client at a time; the dashboard remains the HTTP interface.
2. **No logic in the MCP layer.** The shared operations were moved out of the CLI into `src/core/actions.ts` (`offresALire`, `noterOffres`, `preparerCandidature`, `suivreCandidature`) and are called by the CLI, the API and the MCP server. Each call records its origin (`cli`, `interface`, `mcp`) in the history.
3. **MCP errors as results** (`isError: true`, message in French) rather than as protocol exceptions: the AI reads the cause and corrects its call; the server keeps running. stdout is reserved for the protocol, everything else goes to stderr.
4. **Windows: three documented ways to launch.** Checked on Windows 11 with Claude Code 2.1.314: `vigie-emploi mcp` (`npm link` binary), `cmd /c vigie-emploi mcp` and `node <chemin>/bin/vigie-emploi.js mcp` all connect. A `spawn` without a shell fails on `vigie-emploi` (`ENOENT`, npm creates a `.cmd`): generic clients use the `node` or `cmd /c` form.
5. **Migration 0002**: the `candidatures` table gains `prochaine_action` (+ `prochaine_action_origine`), `libelle` (Offer cell of the tracker, in Markdown), `conditions` (Type cell), `etat` (imported Status or Outcome cell) and `maj_le`. These columns hold what the import used to lose and what the generated tracker must give back.
6. **Updating an application**: absent field = unchanged, `null` or `''` = cleared (sprint 1 could not clear a field). A sending date moves an offer not yet sent to `envoyee`; "DD/MM/YYYY" is stored as ISO, free text ("≈ 25/08/2026", "après le 20/08/2026") is kept as it is.
7. **Next action: what is typed in wins over the import.** `import-historique` only replaces the next action if it came from the import itself (`prochaine_action_origine` empty or `import-suivi`).
8. **Generated tracker, preview first.** `generer-suivi` writes `candidatures/_SUIVI.genere.md`; `--remplacer` writes `_SUIVI.md`. At the top, "Fichier généré par vigie-emploi … ne pas éditer à la main" (file generated by vigie-emploi, do not edit by hand); `import-historique` recognises this mark and does not re-read a generated tracker (otherwise it would reinterpret its own status texts).
9. **Rules of the generated tracker.**
   - Rows: offers in `go` and the statuses after it, and any offer that has an application.
   - Status used: the latest status other than those from the register and batch imports (an offer seen again in an alert batch does not change the state of an application).
   - Text of the Status / Outcome column: the imported cell (`etat`) as long as the latest status is the imported one; after that, the comment of the latest status, or failing that its label and the score.
   - Sections: In progress; Sent with no follow-up (sent or followed up, state "sans nouvelles" or "sans réponse" (no news, no answer)); Closed (rejection, closed, withdrawn, dismissed).
   - Sorting: to send first, then from the latest sending to the oldest; closed ones from the most recent to the oldest (date written in the outcome), those without a date at the end.
   - Links relative to `candidatures/`, to `dossier-candidature.md` if it exists, otherwise to the folder.
10. **Register: grouped rows.** Companies separated by "·", "/" or, failing that, one per bold block; "(×3)" counts three offers. Distribution by job title segment when the numbers match (sprint 1), otherwise **by offer link, in order**, when the number of companies (multiplicities included) equals the number of links; otherwise the whole cell. A new import corrects the existing offers whose company was the whole cell.
11. **Tracker / register duplicates without a link.** A tracker row without an offer link is attached to the `registre` offer of the same company (comparison ignoring case and accents) whose job title shares a word of at least 4 letters, if that offer is unique. A duplicate created by an earlier import is merged into it (`fusionnerOffres`: scores, statuses, tags and application moved, empty fields filled in, duplicate deleted). The offer kept is the one from the register, found again at each import by its key: the import stays idempotent.

## Consequences

- The order of the rows of the generated tracker follows a rule and no longer the manual order; the former section "Anciennes, sans réponse connue" (old, no known answer) is merged into "Sent with no follow-up", with all the columns.
- The distribution by link is positional: correct if the order of the companies follows the order of the links, which is the register's convention.
- The MCP SDK pulls in Express and a few dependencies; they are only loaded by `vigie-emploi mcp`.
